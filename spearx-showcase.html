SpearAI  ·  agent canvas

Your analysts get a team, not a chat box.

Specialist agents hand work to each other on a canvas you can watch, pause and take over. They share one evidence store, so nothing is asked twice, and nothing that changes your estate happens without an analyst approving it.

  • Triage, enrichment, correlation, hunt and response each run as their own agent with its own tools and limits.
  • Every step is recorded with its inputs, outputs, tool calls and cost, so a run can be replayed and audited.
  • Containment waits at an approval gate. The agent proposes, a named analyst decides.

Threat intelligence

Intelligence that lands on your assets, not in a PDF.

Feeds are normalised, deduplicated and confidence-scored, then matched continuously against your own telemetry. You see which indicators actually touched your estate, on which host, at what time, and what the agents did about it.

  • Actor and campaign tracking mapped to ATT&CK techniques, so intel arrives as detection logic rather than reading material.
  • Confidence and decay scoring retires stale indicators instead of letting them generate noise forever.
  • Retro-hunt sweeps every new indicator back across your history the moment it lands.

Entity risk

Risk that points at a name, not a number.

Every user, host, service account and workload carries a risk score built from its own behavioural baseline and its peer group. The score is never a black box: the contributing signals are listed, weighted and clickable down to the raw event.

  • Behavioural baselines per entity and per peer group, so “unusual” means unusual for that account, not for the average one.
  • Score movement is explained by its drivers, with the weight each one contributed.
  • Watchlists and risk thresholds feed the agents directly, raising scrutiny before an incident, not after.

MITRE ATT&CK coverage

Know what you would catch before someone asks you.

Every detection in SpearX is mapped to the techniques it covers, so coverage is a measured property of your deployment rather than a claim on a slide. The gaps are listed with the telemetry that would close them.

  • Technique-level coverage computed from the detections and telemetry you actually have connected.
  • Gaps come with the missing log source or rule named, so the next step is concrete.
  • Observed techniques from live incidents overlay the same matrix, showing coverage against what is hitting you.

Analysis canvas

The whole investigation on one surface.

The canvas is the case file. Entities, the path between them, the timeline and every artefact sit together, so an analyst pivots across identity, endpoint, network and cloud without changing tool or losing the thread. SpearAI lays out the first draft of the graph; the analyst edits it.

  • Pivot from any node to every related event, with the ATT&CK technique on the edge that connects them.
  • Agent hypotheses are shown with their confidence and the evidence that confirmed or killed them.
  • Export the canvas straight into a case, a report, or a detection rule for what you just found.

Vulnerability management

Patch what an attacker can actually reach.

A severity score on its own cannot tell you what to fix first. SpearX narrows every finding by exposure, exploit availability, network reachability and the value of the asset behind it, so the queue your engineers get is short and defensible.

  • Prioritisation chain you can inspect and tune, with the rule behind every stage shown.
  • Remediation campaigns with owners and SLAs, tracked against the ticketing system you already use.
  • Known-exploited and actively-targeted findings are promoted automatically from the intel module.

Cloud security posture

Cloud posture, with the path to your data drawn.

Misconfigurations across AWS, Azure and GCP are mapped to the control that fails and the framework that requires it. SpearX then chains them into the paths that actually reach sensitive data, so a public bucket and an over-permissive role stop being two separate tickets.

  • One control library behind every cloud, so posture is comparable across providers instead of per-console.
  • Attack paths chain identity, network and data findings into a single ranked route.
  • Framework evidence is collected continuously, so an audit is an export rather than a project.

File integrity monitoring

Know the moment a file changes, and who changed it.

Baselines, hashes and permissions on the paths that matter, with the process and account behind every change. Each change is checked against your approved change windows and tickets, so routine deployment noise separates itself from the one edit nobody authorised.

  • Before and after hashes with the diff for text and configuration files.
  • Changes correlated against change tickets and maintenance windows, so unauthorised means unauthorised.
  • Baseline drift tracked per path, with one click to re-baseline after an approved release.

CQS analysis

One score your board can follow month to month.

CQS rolls detection coverage, cloud posture, exposure, identity hygiene and response performance into a single trendable number, and then shows exactly which drivers moved it. Every component is traceable back to the module that produced it, so the score survives the question “where does that come from?”.

  • Six weighted components, each one a live measurement rather than a questionnaire answer.
  • Month-on-month movement attributed to named drivers, with the work that caused the change.
  • Weights are yours to set, so the score reflects the risks your organisation actually cares about.

Custom dashboards

Build the view your team actually runs on.

Drag any widget from any module onto a shared canvas. A SOC lead, a cloud team and an audit committee need three different pictures of the same data, and none of them should need a ticket to get one.

  • Widgets from every module on one canvas, bound to the same filters and time range.
  • Share with a team, embed in a wiki, or schedule as a snapshot to an inbox.
  • Any widget opens into the module it came from, with your filters carried through.

Reporting

The report writes itself from the evidence.

Reports are generated from the same evidence store the agents wrote to, so the executive summary, the technique list and the remediation table all reconcile with the case they came from. Pick the audience, pick the period, and the document is ready with its figures already sourced.

  • Executive, technical and audit templates drawn from one data set, so versions cannot drift apart.
  • Every figure in the document links back to the query and artefacts that produced it.
  • Scheduled distribution per audience, with classification and retention applied automatically.

About these screens

Every interface on this page is an illustrative build of the SpearX product populated with synthetic demo data. Host names, accounts, indicators, findings and scores are invented for demonstration. External addresses use the IETF documentation ranges reserved for examples (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) and never route anywhere. MITRE ATT&CK tactic and technique identifiers are real and published by MITRE; the coverage values shown against them are not.
